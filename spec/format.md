# Формат файла токенизатора (v1)

Один JSON-файл, который читают и пишут и Python-, и Rust-версии.

## Пример

```json
{
  "version": 1,
  "pattern": "'s|'t|'re|'ve|'m|'ll|'d| ?\\p{L}+| ?\\p{N}+| ?[^\\s\\p{L}\\p{N}]+|\\s+(?!\\S)|\\s+",
  "vocab_size": 1024,
  "merges": [[116, 104], [256, 101]],
  "vocab": ["00", "01", "...", "7468", "746865"],
  "special_tokens": {"<|endoftext|>": 1023}
}
```

## Поля

| Поле             | Тип                  | Описание                                                                 |
|------------------|----------------------|--------------------------------------------------------------------------|
| `version`        | int                  | Версия формата, сейчас `1`                                               |
| `pattern`        | string               | Регулярка пре-токенизации (копия `spec/pattern.txt`)                     |
| `vocab_size`     | int                  | Полный размер словаря, включая 256 байт, merges и спецтокены             |
| `merges`         | list[[int, int]]     | Пары id в порядке обучения; индекс = приоритет (меньше = раньше)         |
| `vocab`          | list[string]         | Байты каждого обычного токена в hex; индекс в списке = id токена         |
| `special_tokens` | dict[string, int]    | Спецтокен → id                                                           |

## Нумерация id

- `0..255` базовые байты: токен с id `i` это один байт со значением `i`.
- `256 + k` токен, полученный k-м слиянием (`merges[k]`), k считается с нуля.
- Спецтокены получают id после всех merges: `256 + len(merges) + j`, где `j` порядковый номер спецтокена.
- Количество слияний: `len(merges) = vocab_size - 256 - len(special_tokens)`.

## Правила и инварианты

1. `len(vocab) == 256 + len(merges)`.
2. `vocab[i]` для `i < 256` это hex одного байта, например `vocab[65] == "41"`.
3. `vocab[256 + k] == vocab[merges[k][0]] + vocab[merges[k][1]]` (конкатенация байтов).
4. Hex пишется строчными буквами, без префикса `0x`, по два символа на байт.
5. В каждой паре `merges[k]` оба id строго меньше `256 + k` (нельзя использовать ещё не созданный токен).
6. Спецтокены не входят в `vocab`, и их строки не участвуют в слияниях.
7. Порядок `merges` и есть приоритет при encode: применяется слияние с наименьшим индексом.
8. Кодировка файла UTF-8, ключи в фиксированном порядке (как в примере), чтобы файлы двух реализаций можно было сравнивать через `diff`.

## Детерминизм обучения

Из корпуса и параметров список `merges` определяется однозначно:

- на каждом шаге выбирается пара с максимальной частотой;
- при равной частоте выбирается пара с наименьшим `(id_left, id_right)`.

## Проверка корректности файла

Загрузчик в обеих реализациях должен проверять инварианты 1-3 и 5 и падать с понятной ошибкой, если файл их нарушает.
